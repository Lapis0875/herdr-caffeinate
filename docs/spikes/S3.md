# S3 — Spike: timer gaps with the lid closed

Node S3 of `plan/herdr-caffeinate.md` (wave 1). Decides whether the engine's own
Herdr timers can keep the claim heartbeat fresh with the lid shut (C11), or
whether the D10 keeper (C11a) is needed. Feeds T5, AT-08 and AT-21.

## Decision

| Item | Decision |
| --- | --- |
| Engine timers vs D10 keeper (rule: engine timers if the largest gap is ≤ 30 s, else the keeper; > 400 s returns to the owner) | **Engine timers.** The largest gap of the 10 s `cx.timer.every(…, {owner: null})` over the 2968 s window was **10.199 s**: 0 gaps > 15 s, > 30 s or > 400 s. ## 1. Setup

- **Herdr probe**: a throwaway mod `hc-spike-3` (`mod.json` `{"place":"none"}`, so it was never docked).
  - `herdr-app do mod.open '{"name":"hc-spike-3"}'` opened a popup copy. That copy opened a hidden window copy and closed itself. The window copy was `openOverlay({mod:"hc-spike-3", props:{view:"host"}, kind:"window", frame:"none", key:"hc-spike-3.host", width:2, height:2, at:{x:0,y:0}})`, the same shape as C9's host.
  - The host copy started one module-scope timer, `cx.timer.every(10_000, …, {owner: null})`. Each tick appended `Date.now()` to `<app home>/data/hc-spike-3/ticks.log`, using `fs/promises` read and rewrite calls run one at a time.
  - The timer started once, at `1795107101075` (`boots.log` has a single `start` line), and ran without a restart until cleanup.
  - API checked in `gpui-kit.d.ts:20646-20653` (`Timer.every`: "The interval is measured from the end of one call") and `:22054-22058` (`TaskOptions.owner`).
- **Shell control**: `/bin/sh /tmp/hc-s3-shell-loop.sh`, started with `nohup … &` in its own process group (pid 8477, pgid 8477).
  - Every 10 s it appended one line: `<date +%s> AppleClamshellCausesSleep=… AppleClamshellState=… SleepDisabled=… power=…`.
  - The epoch is read first. The clamshell keys come from `ioreg -r -k AppleClamshellState -d 1 | grep -E 'AppleClamshell(State|CausesSleep)'`, flattened to one line. `SleepDisabled` comes from `pmset -g | grep SleepDisabled`.
  - The extra `ioreg`/`pmset` calls make its period about 10–11 s.
- **Analysis**: `/tmp/hc-s3-gaps.sh START END` measures gaps between consecutive ticks. The window is anchored on the last tick at or before START and the first tick at or after END, so a stall that crosses an edge counts in full. `--lid` lists the closed-lid runs in the control log.
- A first probe build ran the timer in the `mod.open` popup copy itself. Closing that copy at 1795106967 stopped the `owner: null` timer: the last tick was `1795106959891` and none came later, although module state survived. That is why the run used a window copy that stayed open. S2 measured this behaviour in detail.

`pmset -g batt` first line: `Now drawing from 'AC Power'`.

The control log shows how the keys moved with `SleepDisabled=1`:

```
1795110142 AppleClamshellCausesSleep=Yes AppleClamshellState=No SleepDisabled=1 power=AC_Power   (02:42:22, lid open)
1795110253 AppleClamshellCausesSleep=No AppleClamshellState=Yes SleepDisabled=1 power=AC_Power   (02:44:13, first close)
1795110263 AppleClamshellCausesSleep=No AppleClamshellState=No SleepDisabled=1 power=AC_Power    (02:44:23, open again)
1795113878 AppleClamshellCausesSleep=No AppleClamshellState=No SleepDisabled=1 power=AC_Power    (03:44:38, opened)
1795113899 AppleClamshellCausesSleep=No AppleClamshellState=No SleepDisabled=0 power=AC_Power    (03:44:59, reset)
```

After the run the external display was unplugged. At 03:46:44, with the lid open and only the built-in display (`Connection Type: Internal`), `ioreg` still read `"AppleClamshellCausesSleep" = No` and `"AppleClamshellState" = No`. S4 measured `CausesSleep = Yes` in that same condition earlier the same night.

What this means:

- **C7 step 5 and C10 `sleepNow`.**
  - With the lid shut in clamshell mode on an external display, `CausesSleep` is `No`, so the watchdog's `restore` does not run `pmset sleepnow`, and the reducer does not set `sleepNow` when closed-lid ends. That is the correct outcome: macOS itself does not sleep on lid close while an external display is in use on AC, so the Mac stays as the user expects.
  - The rule (`State = Yes` and `CausesSleep = Yes`) is kept.
- **`CausesSleep` is not tied to the current display set.** It changed only when the lid closed: it went Yes → No at the first close with the external display attached and stayed No through every later lid-open sample. It was still No after the external display was unplugged, with the lid open.
  - [INFERENCE] powerd recomputes it on clamshell events, so with the lid open it can be stale and means nothing. C10 and C7 already read it only together with `State = Yes`; T2 fixtures should not treat a lid-open `CausesSleep` value as information.
- **Not measured:** `CausesSleep` with the lid shut, **no** external display and `SleepDisabled 1`, which is the case where `sleepnow` must fire. This run had an external display attached.
  - [INFERENCE] The keys are refreshed on the close event, so that case reads `Yes`.
  - If it instead stayed a stale `No` after an external display was unplugged, `restore` would skip `sleepnow`. The Mac would then stay awake with the lid shut until idle sleep.
  - AT-21's second run (sleep via `sleepnow` with the lid shut) covers this case and should be run **without** an external display.

## 4. Limits of this measurement

- The run was clamshell mode with an external display. On AC, macOS would have stayed awake with the lid shut even without `disablesleep 1`, so this run did not test lid-shut **without** a display attached.
  - What it did cover: 37.8 min with the lid shut and every display asleep, so Herdr's windows had nothing to draw to, with no timer slowdown at all (largest gap 10.199 s).
  - [INFERENCE] Timer slowdown in a background app depends on whether its windows can be seen, not on which displays are attached, so the result should hold without an external display.
  - The backstop is AT-21's first run, which should be done with no external display. If engine ticks stalled there, the claim would go stale (> 45 s), the watchdog would restore and put the Mac to sleep, and the 5 s shell log would show a gap.
- One Herdr build, one 50 min window, AC only. Battery was not measured; closed-lid is AC-only by default (`acOnly: true`), and the battery floor and `acOnly` blocks end closed-lid anyway.
- Ticks were written through `fs/promises` with a read and full rewrite per tick (no `appendFile`). This adds I/O per tick but cannot shorten a gap.
