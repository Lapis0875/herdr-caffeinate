# S2: Hidden host window for another mod

**Chosen branch: C9 host.** lazuli opens a frameless 2×2 `kind:"window"` overlay of herdr-caffeinate (`props:{view:"host"}`). That window stays open, cannot be seen in `herdr-app shot`, and receives `herdr-app do herdr-caffeinate.<cmd>` through `nextCommand()`.

**Shared-mailbox fallback: rejected.** In the fallback, the host starts the engine and then closes itself. That does not work, because closing the host stops every `{owner: null}` timer and task the host started, so nothing is left to read the mailbox. The mailbox works only while a copy that runs a timer is alive, and while such a copy is alive `nextCommand()` already delivers commands.

C9 and C11 need the amendments listed under **Consequences** below. They need the owner's confirmation, because CONTRACTS is binding.

## Setup

- Herdr app 0.1.16 on macOS. The live layout was `lazuli` at zoom 0.9. `herdr-app shot` frames were 3024×1898 physical px, which is 2× the logical size.
- Two throwaway probe mods, both with `"place": "none"`:
  - `hc-spike-2a` is the lazuli-like opener. It was opened with `herdr-app do mod.open --name hc-spike-2a`. When it started, it called `openOverlay(HOST)`, the way lazuli would at services start. After that it took commands from a polled file, `data/hc-spike-2a/cmd.txt`.
  - `hc-spike-2b` is the caffeinate-like target. Each copy logged `init`, `close()` and every `nextCommand()` value. A `host` copy started a module-scope singleton engine with three variants:
    - **A:** `cx.timer.every(2000, …, {owner: null})`
    - **B:** `cx.spawn(async (cx) => { for (;;) { await cx.sleep(2000); … } }, {owner: null})`
    - **C:** a `cx.timer.every(…, {owner: null})` started from inside B's owner-less `cx`

    Every tick read and cleared the shared key `hc-spike-2b.request`.
- `HOST` was exactly the spec under test:
  `{mod:"hc-spike-2b", props:{view:"host"}, kind:"window", frame:"none", key:"hc-spike-2b.host", width:2, height:2, at:{x:0,y:0}}`.
- Both probes logged by appending one line per event under the app home: `<app home>/data/hc-spike-2{a,b}/log.txt`, written with `exec("/bin/sh", ["-c", 'printf … >> …'])`. Timestamps are ms epoch. Every 2b line carries its build tag `[b:<id>]`.

Other observations:
- `openOverlay` with `at:{x:0,y:0}` put the 2×2 window at physical (92, 0), which is 46 logical px from the window's left edge, in the lazuli layout (`traffic_lights` [12,16], zoom 0.9). The cause was not determined. The window covers 4×4 physical px of the lazuli brand bar, which is a `window_drag` area. **[INFERENCE]** A press on exactly that spot would drag the invisible window instead of moving the app window.
- `openOverlay` called from a task spawned in the opener's `init` returned ids such as `"o9"`. The host got `props()` = `{"view":"host","overlay":"o9"}`.
- The host rendered once when it opened and again on shared-state changes: the `render()` count rose 8 → 9 → 10 around the two `setShared` calls in the mailbox test. It does not render on its own otherwise.
- Saving a mod's `main.js` reloads each open overlay copy in place under the same overlay id (`init host@o10` with new build `mwnsfrgi`), and the old build's timers stop. **[INFERENCE, not isolated]** The first 2b build logged by chaining `fs.writeFile` calls. After its docked copy closed (see Hazards), that build never wrote another line, although its `o9` copy existed. A pending `fs` call of the closed copy probably never settled and stalled the chain. Promise chains through calls made by a copy that can close should be avoided.
- `setShared(key, undefined)` returns `null` and stores `null`. The key stays in `shared.json`, and the API offers no way to delete it.

## Consequences for C9 / C11 (proposed; owner confirmation needed)

1. **C9:** lazuli opens the host **on every lazuli services start**: at Herdr start, and each time the lazuli layout shows again after a switch, because a layout switch closes the window. Do not set `keep`. lazuli reopens the window itself, and a kept window would reopen as well, replacing the host and restarting the engine for no reason. The S2 fallback paragraph (mailbox) should be removed.
2. **C11, engine lifetime:** the engine lives only as long as the copy that started it. `{owner: null}` does not let it outlive that copy.
   - The starting copy's `close()` must stop the engine and clear the module-scope `started` flag.
   - Every host copy must run a default-owner check (in `init`, plus a slow timer such as 5 s) that starts the engine whenever no live copy owns it. This covers same-key replacement, where the new copy's `init` and the old copy's `close()` landed in the same millisecond, so their order is not known.
   - Transient copies (the menu popover) must not start the engine. If no host is open, they should open the host themselves, with the same `key`.
3. **C11, resume:** every restart resumes from `runtime.json` and `settings.json`, as after a reload: adopt the holder and keeper, and re-check `endsAt` (a timer that ended while no engine ran turns Off on the first step).
4. **Gap while no host runs.** This happens when another layout without lazuli shows, or for the moment between close and reopen. No engine ticks, and the claim heartbeat stops. **[INFERENCE]** After STALE = 45 s, the C7 watchdog restores `disablesleep 0`, so closed-lid ends, and agent/timer transitions wait for the next host. S1/S3 and the owner should decide whether that is acceptable or whether herdr-caffeinate should open its own host in every layout.
5. **C1:** because commands fan out to every shown copy, "only the first-registered live copy handles a command" is required. `herdr-app do herdr-caffeinate.*` exits 1 ("need the mod loaded") whenever no copy is shown. Scripts and tests must expect that.

## Hazards found while probing

- **Auto-dock.** Herdr saw the new folder `mods/hc-spike-2b/` with `main.js` before `mod.json` (`"place":"none"`) existed. It docked the mod into the live layout: it rewrote `layouts/lazuli.json` with an extra root block `{mod:"hc-spike-2b", size:{px:320}}` (S1's `hc-spike-1` got the same). Main restored the file from the repo copy.
  - Any install or copy of `mods/herdr-caffeinate/` must make `mod.json` appear before or together with `main.js`, for example by copying to a temp name and renaming the folder.
- Herdr writes `gpui-kit.d.ts` and `jsconfig.json` into a mod folder once it has loaded the mod.
