# S1 — Spike: detached caffeinate holder from `exec`

Run: 2026-11-20 01:45–01:52 (+0900), macOS 27.0 (26A428), `herdr-app 0.1.16`, Herdr pid 56192
(`/Applications/Herdr.app/Contents/MacOS/Herdr`), on AC power (`Now drawing from 'AC Power'`).
Probe: throwaway mod `~/.config/herdr-app/mods/hc-spike-1/` (overlay window, commands through
`herdr-app do hc-spike-1.<cmd>`), removed after the run. Herdr was never killed (AT-05 is the owner's).

## Answers

| Question | Answer |
| --- | --- |
| Is `$PPID` in `exec("/bin/sh", ["-c", …])` (no `on`) the Herdr pid? | **Yes.** `PPID=56192` in all 4 probes; `pgrep -x Herdr` from outside Herdr = `56192`. |
| Does `pgrep -x Herdr` work inside `exec`? | **No**: it prints nothing (macOS `pgrep` excludes its own ancestors). `pgrep -a -x Herdr` prints `56192`. |
| Does a `nohup … &` child survive `exec` returning? | **Yes** (and so do plain `&`, `( … & )`, `( nohup … & )` and a perl `setsid` form). |
| Does it survive a mod reload (re-save of `main.js`)? | **Yes**, 4 reloads (build-1 → build-5). |
| Does it survive closing the copy (overlay closed)? | **Yes.** |
| Does it survive an `exec` timeout or a reload while its `exec` is still running? | **Yes**, both. |
| Does `pmset -g assertions` list it? | **Yes**: `PreventUserIdleSystemSleep` and `PreventSystemSleep` (plus `PreventUserIdleDisplaySleep` with `-d`), "on behalf of Process ID 56192". |
| Does it die with `-w`? | caffeinate(8): "Once the process exits, the assertion is also released". Measured on a stand-in target (SIGKILL): the holder is gone at the first check, ≤ 2 ms. Herdr itself not killed (AT-05). |
| `setsid` | Not installed on macOS (`which setsid` finds nothing); `/usr/bin/perl -MPOSIX` works but is not needed. |

**Chosen launch form (holder and keeper):** `nohup "$@" >/dev/null 2>&1 & echo "$!"` run through
`exec("/bin/sh", ["-c", DETACH, "sh", ...argv])`. The `-t 120` lease fallback is **not needed**.

## Chosen launch form

```js
// sys/: one detached launcher for the holder and the keeper. No `on` (must run locally, child of Herdr).
const DETACH = 'nohup "$@" >/dev/null 2>&1 & echo "$!"';
async function launchDetached(argv) {
  const r = await exec("/bin/sh", ["-c", DETACH, "sh", ...argv]);
  const pid = Number(r.stdout.trim());
  return r.code === 0 && Number.isInteger(pid) && pid > 1 ? pid : null;
}

// Herdr pid: once per engine start (never during checking()).
const appPid = Number((await exec("/bin/sh", ["-c", 'echo "$PPID"'])).stdout.trim());

// Holder (C11): argv exactly as C11 / AT-01 expect.
launchDetached(["/usr/bin/caffeinate", "-i", "-s", ...(display ? ["-d"] : []), "-w", String(appPid)]);
// Keeper (C11a, D10 branch only).
launchDetached(["/bin/sh", `${appHome()}/mods/herdr-caffeinate/bin/keeper.sh`, String(appPid), claimPath, enginePath]);
```

Why this form:
- `$!` is the final pid: `nohup` execs the utility, so the recorded pid is the caffeinate (or keeper `sh`) pid.
- Arguments travel as positional parameters (`"$@"`), so paths with spaces need no quoting.
- `>/dev/null 2>&1` closes Herdr's pipes for the child, so `exec` resolves at once (11–29 ms measured);
  without it the `exec` promise waits for the child's pipe ends.
- `nohup` adds SIGHUP immunity; no other form behaved differently in this run.
- Exactly this form (with `-d`) and the keeper form were run from the probe (`generic`, `generic-keeper`) and survived exec return, a reload and the overlay close.

## Facts for T5 (engine / holder implementer)

1. **Process tree.** The `exec` child `sh` has PPID = Herdr and PGID = Herdr's own pgid (`56192`); Herdr does
   not give an `exec` its own process group. After `exec` returns the detached child is reparented to
   launchd (PPID 1) and keeps PGID 56192 (`setsid` form: its own session/group, `Ss`). A signal sent to
   Herdr's process group would also reach the holder (fail-safe direction).
2. **argv race right after launch.** `ps -o command= -p $!` read immediately can still show
   `nohup /usr/bin/caffeinate …` (1 of 5 runs at 0 ms, 0 of 5 after 50 ms). Record the argv you launched
   and verify argv only at adoption or kill time, never immediately after the launch.
3. **Reload drops in-flight `exec` results.** In the `inflight` probe the old build's task never logged its
   result after the reload (the `sh` itself ran to completion and its caffeinate survived). A reload that lands
   between the launch `exec` and the `runtime.json` write leaves a holder the next engine does not know. See
   open issue 1.
4. **`exec` timeout** stops only the direct `sh` ("`herdr.exec`: /bin/sh took longer than 2 s and was stopped");
   its detached caffeinate survived. The default 30 s timeout is ample for the launcher.
5. **Stopping.** `kill <pid>` (TERM) ends caffeinate and its assertions (0 caffeinate assertion lines after).
   TERM to a keeper `sh` while it sleeps orphans its `/bin/sleep` until that sleep ends (none left 2.5 s after
   with `sleep 2`; with keeper's `sleep 10` an orphan `sleep` lives ≤ 10 s, harmless).
6. **`-w` + `-t` combine as "whichever comes first"**; `-w <pid that does not exist>` exits immediately with 0.
7. **Probe mods / new mod folders:** write `mod.json` (with `"place": "none"`) **before** `main.js`. In this run
   `main.js` was saved a few seconds before `mod.json` (`init` logged at 01:48:22 and again at 01:48:28), and Herdr docked the probe into the shown layout
   (`layouts/lazuli.json`, a 320 px root block); Main restored the layout. The same applies to installing
   `mods/herdr-caffeinate/`: copy `mod.json` first.
8. `herdr-app do <mod>.<cmd>` exits 1 when no copy of the mod is shown (observed after the docked copy was
   removed and before the overlay was opened); with the overlay open it exits 0 (`{"ok": true}`).

## Open issues

1. **Untracked holder after a mid-launch reload** (fact 3) could break AT-01's "exactly one process". Suggested
   for T5 (no contract change needed, C11 already kills only after pid+argv match): on engine boot, after
   adopting from `runtime.json`, list `/bin/ps -axo pid=,command=` and kill (argv-verified) every other process
   whose command is exactly `/usr/bin/caffeinate -i -s -w <appPid>` or `/usr/bin/caffeinate -i -s -d -w <appPid>`.
   Main decides whether this belongs in C11.
2. Herdr-death behaviour (`kill -9` Herdr → holder gone ≤ 5 s) is inferred from caffeinate(8) and the stand-in
   test below; the owner verifies it in AT-05.
3. `~/.config/herdr-app/seen.json` still lists `hc-spike-1` (Herdr's own record of seen mod folders); not edited.

## caffeinate(8) excerpt

```
-s      Create an assertion to prevent the system from sleeping. This
        assertion is valid only when system is running on AC power.
-t      Specifies the timeout value in seconds for which this assertion
        has to be valid. The assertion is dropped after the specified
        timeout. Timeout value is not used when an utility is invoked
        with this command.
-w      Waits for the process with the specified pid to exit. Once the
        the process exits, the assertion is also released.  This option
        is ignored when used with utility option.
```
