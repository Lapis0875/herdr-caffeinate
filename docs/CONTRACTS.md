**C1 Commands** (`herdr-caffeinate.<command>` through keys, `run()` or `herdr-app do`): `toggle` (Off ↔ last of `on`/`agent`), `mode:off`, `mode:on`, `mode:agent`, `timer:<minutes>` (integer 1..1440), `timer:cancel`, `display:on|off|toggle`, `closed-lid:on|off|toggle`, `menu` (open the popover), `refresh` (re-read `settings.json`, probe and step at once), `install`, `uninstall` (open a Herdr tab running `bin/install.sh` / `bin/uninstall.sh` via `tab.new {argv}`). Unknown or malformed commands are ignored with one `console.log` line. Only the first-registered live copy handles a command. Shipped `keys.json` binds `"mod.open:herdr-caffeinate"` under `global` on a key T7 confirms free in the owner's `keys.json`.

**C2 Settings** `<app home>/data/herdr-caffeinate/settings.json`, written with `writeTextFile(path, text, expected)`; unknown fields kept, invalid fields fall back to defaults:
```json
{ "version": 1, "language": "system", "mode": "off", "display": false,
  "timer": { "presetsMin": [15, 60, 120], "lastCustomMin": 45 },
  "agent": { "lingerSec": 30, "includeRemote": false },
  "closedLid": { "enabled": false, "acOnly": true, "batteryFloor": 20 },
  "trigger": { "ac": { "enabled": false, "mode": "on" } },
  "debug": false }
```
`batteryFloor` clamps to 10..90. `mode` persists and resumes at Herdr start; a timer resumes only while `endsAt` is in the future. Runtime state `<app home>/data/herdr-caffeinate/runtime.json`: `{v:1, session:{mode, origin:"user"|"trigger", startedAt, endsAt|null}|null, holder:{pid, argv, appPid}|null, keeper:{pid, argv}|null, trigger:{suppressed, lastAc}, lastMode:"on"|"agent"|null}` (`lastMode` is what `toggle` returns to after a restart; review fix, owner-approved 2026-11-21). With `debug: true` the settings may carry `fake: {ac?, percent?, thermal?, lidClosed?}` that override probe facts for live engine checks.

**C3 Shared key** `herdr-caffeinate.state` (the only thing other mods read), republished on engine boot and on change, never per tick:
```json
{ "v": 1, "at": 1763568000000, "mode": "off|on|agent|timer", "active": true,
  "reason": "user|agent|timer|trigger|null", "display": false, "endsAt": null,
  "closedLid": { "wanted": false, "status": "off|engaged|blocked|unavailable|external",
    "blocked": "ac|battery|thermal|unknown|other-instance|null" },
  "install": { "sudo": true, "failsafe": true } }
```
Every publish also writes the same object to `<app home>/data/herdr-caffeinate/state.json` for scripts and tests ("read C3" below means `jq . ~/.config/herdr-app/data/herdr-caffeinate/state.json`). On every tick, every poke, every menu open and on `refresh` the engine reads `settings.json` and applies it when the text differs from the last text it read (`fs/promises` has no `stat`), so an edit made outside Herdr (e.g. with `jq`) applies within one tick, or at once after `herdr-app do herdr-caffeinate.refresh`.

**C5 Probe** `bin/probe.sh [--thermal]`: read-only, exit 0, no parsing; prints sections `@@batt` (`pmset -g batt`), `@@pmset` (the `SleepDisabled` line of `pmset -g`), `@@lid` (`AppleClamshellState` and `AppleClamshellCausesSleep` from `ioreg -r -k AppleClamshellState -d 1`), `@@thermal` (`osascript -l JavaScript -e "ObjC.import('Foundation'); $.NSProcessInfo.processInfo.thermalState"`), `@@stat` (`alive=`, `claim=`, `restore=`, `now=` epoch seconds or empty). `core/probe-parse.js` `parseProbe(text)` → `{ac, percent, sleepDisabled, lidClosed, lidCausesSleep, thermal, failsafeAliveAge, claimAge, lastRestore, now}`, each `null` when unreadable; never throws.

**C6 Sudoers** — exactly one rule line; `__USER__` replaced only after matching `^[a-z_][a-z0-9_-]*$`:
```
__USER__ ALL = (root) NOPASSWD: /usr/bin/pmset -a disablesleep 0, /usr/bin/pmset -a disablesleep 1
```
The mod only runs `exec("/usr/bin/sudo", ["-n", "/usr/bin/pmset", "-a", "disablesleep", "0"|"1"])`; a non-zero code means not permitted; it never prompts. `sys/privilege.js` reports `install.sudo` = `sudo -n -l /usr/bin/pmset -a disablesleep 0` and `… 1` both exit 0, and `install.failsafe` = `/var/db/herdr-caffeinate/alive` age ≤ 60 s. Closed-lid needs both; since D9 the installer installs our rule regardless of other rules.

**C7 LaunchDaemon** label `io.github.lapis0875.herdr-caffeinate.failsafe`; `ProgramArguments` `[/bin/sh, <helper path>, <HOME>/.herdr/herdr-caffeinate/claim]`; `StartInterval` 15; `RunAtLoad` true; `ProcessType` Background; no `KeepAlive`, no `WatchPaths`. Watchdog (`STALE=45`, `WAKE_GRACE=60`, `FLOOR=10`; fixed `PATH`, absolute tool paths, `set -u`, no `eval`/`source`):
1. Reject `$1` unless it matches `/Users/*/.herdr/herdr-caffeinate/claim` without `..`; touch `alive`.
2. Claim is a regular non-symlink file with age ≤ STALE: if `SleepDisabled` is 1, create `armed`, or touch it when `released` is at least as new (a re-engage after a release inside one interval re-arms, so a later claim loss without a release still restores); if `armed` exists and the Mac is on battery below FLOOR %, `restore battery-floor`. Exit.
3. Claim stale: if its mtime equals the content of `handled`, exit; if the Mac woke less than WAKE_GRACE s ago (`sysctl -n kern.waketime`, format fixed by S4), exit; else `restore stale-claim` and write the mtime to `handled`.
4. No claim: if `armed` exists and `released` is a regular non-symlink file whose mtime is ≥ the mtime of `armed`, our own disengage already restored 0: remove `armed` and write nothing else (a later foreign `disablesleep 1` is never touched); if `armed` exists without such a `released`, `restore claim-gone`; otherwise write nothing.
5. `restore <reason>`: `/usr/bin/pmset -a disablesleep 0` only if `SleepDisabled` is 1; remove `armed`; write `<epoch> <reason>` to `last-restore`; if `AppleClamshellState = Yes` and `AppleClamshellCausesSleep = Yes`, `/usr/bin/pmset sleepnow`.

**C8 Installer** `bin/install.sh` (run as the user in a Herdr tab; calls `sudo` itself): refuse uid 0; validate user and home; render sudoers to a temp file, `visudo -cf`, install 0440, then verify our installed file alone with `sudo visudo -cf /etc/sudoers.d/herdr-caffeinate` and the rule with `sudo -n -l /usr/bin/pmset -a disablesleep 0` and `… 1` (failure: remove, exit 10); a whole-config `sudo visudo -c` is run only to print other files' warnings as notes and never fails the install (owner-approved 2026-11-20, after Amphetamine's 0644 `amphetamine_PowerProtect` made it fail); install the helper and `/var/db/herdr-caffeinate` (failure: exit 20); render the plist, `plutil -lint`, install, `launchctl bootout` (ignored), `launchctl bootstrap system <plist>`, wait until `alive` is fresh (failure: exit 30); exit 0. `bin/uninstall.sh`: restore `disablesleep 0` only if `claim` exists, or `armed` exists without a `released` at least as new (C7 step 4); `bootout`; remove plist, helper, state dir, sudoers file; then, as the user, remove `~/.herdr/herdr-caffeinate/claim` and `released` (only those files; a symlink itself, not its target) so a later install's watchdog never restores a foreign `disablesleep 1` (review fix, owner-approved 2026-11-21); check that `/etc/sudoers.d/herdr-caffeinate` and the claim are gone (a whole-config `sudo visudo -c` only prints notes); print a note if `SleepDisabled` is still 1 from another tool; exit 0, or 40 on partial removal.

**C9 lazuli integration** (lazuli imports nothing from this mod): on every lazuli services start (layout start or switch to lazuli, mod reload) lazuli checks `fs.exists("<app home>/mods/herdr-caffeinate/mod.json")`. **C10 Reducer** `core/machine.js` `step(state, event, facts, settings) → {state, desired:{awake, display, closedLid, sleepNow}, effects}`; events carry `now`.
- Awake: `on`; `agent` with working > 0 or within `lingerSec` of the last working time; `timer` with `now < endsAt` (at `endsAt` the mode becomes Off).
- Closed-lid wanted: `closedLid.enabled && awake`, unless blocked. Block priority: `unavailable` > `other-instance` > `external` > `thermal` (≥ 2) > `battery` (on battery and percent < floor) > `ac` (`acOnly` and not on AC) > `unknown` (3 consecutive unreadable probes). Battery clears at floor + 5 or on AC; thermal clears after 2 probes ≤ 1. `closedLid.status` is `external` whenever `SleepDisabled` is 1 and we hold no claim, whatever `closedLid.enabled` is; otherwise `off` when not wanted.
- `sleepNow` on every engaged → not-engaged transition while `lidClosed && lidCausesSleep` (D7). While `lidClosed && lidCausesSleep` and closed-lid is not engaged, `desired.awake` is false (no holder; a running holder is stopped before `pmset sleepnow`, because its `PreventSystemSleep` assertion turns the software sleep into a dark wake on AC — AT-21, hc-c3); when the lid opens, or `lidCausesSleep` reads No (clamshell with an external display), the holder follows the mode again (owner-approved 2026-11-20).
- AC trigger: an AC 0→1 edge with mode Off and not suppressed starts a `trigger` session; AC 1→0 ends only trigger sessions and clears the suppression; a user Off while on AC sets the suppression.

**C11 Engine and holder** (`sys/`): a module-scope singleton started from a host or chip copy's `init` unless `checking()`, timers with `{owner: null}`; tick 10 s while a claim is held, 30 s while a session is active or the AC trigger is on, none otherwise; with `debug: true` the tick is always 10 s; each tick: probe → `step` → reconcile holder and closed-lid → touch the claim → publish C3 if changed; every copy's `render()` calls `engine.poke()` (debounced 250 ms); opening the menu (view or `menu` command) runs a probe and a step at once. Engine lifetime (S2, S3): `owner: null` timers and tasks stop when the copy that started them closes, so the engine records which copy started it; that copy's `close()` marks the engine stopped (it releases nothing), and the next host or chip copy's `init`/`render` restarts it, resuming from `runtime.json` and `settings.json`; popover (menu) copies open the host instead of starting the engine; every chip copy opens the host when none is open. With no copy shown (a layout without the chip or lazuli) the engine does not run: closed-lid is restored by the watchdog within 60 s; a timer holder still ends at `endsAt` through its `-t`; On and Agent holders stay until the engine returns or Herdr exits (owner-approved 2026-11-20). Agent count: `terminals()` entries with `status === "working"` and `state === "live"`, local (address without a `machine/` prefix) unless `includeRemote`. Holder: detached through `exec("/bin/sh", ["-c", 'nohup "$@" >/dev/null 2>&1 & echo "$!"', "sh", "/usr/bin/caffeinate", "-i", "-s", ("-d",) "-w", <Herdr pid>, ("-t", <whole seconds until endsAt>)])` — `-t` only for timer sessions (S1; the Herdr pid is `$PPID` of that shell); adopted after reload from `runtime.json` after checking `ps -o command= -p <pid>` (not right after launch: `ps` may briefly show the `nohup` argv); killed only after pid and argv match. At engine boot, after adoption, every other process whose argv is exactly `/usr/bin/caffeinate -i -s [-d] -w <this Herdr pid> [-t <n>]` is an orphan of a reload that lost the launch result and is killed after its argv is checked, so at most one holder exists (owner-approved 2026-11-20). Quit is treated like a crash: `close()` never releases. Closed-lid engage: if `SleepDisabled` is 1 and we hold no claim → `external`, touch nothing; else write claim, `sudo -n pmset … 1`, read back (failure: remove claim, `unavailable`). Disengage: `sudo -n pmset … 0`, read back; when it reads 0, touch `~/.herdr/herdr-caffeinate/released` (through `exec`, like the claim) and then remove the claim (owner-approved 2026-11-21, AT-09 race); `pmset sleepnow` if `sleepNow`. `last-restore` newer than our engage with conditions still holding → re-engage once with a toast; `SleepDisabled` flipped to 0 without `last-restore` → user override: `closedLid.enabled = false` and a toast.

**C11a Keeper** (only when S3 selects the D10 branch): `bin/keeper.sh <Herdr pid> <claim path> <engine path>`, started detached by the engine (launch form from S1) when it writes the claim, after the engine has touched the `engine` file; its pid and argv go into `runtime.json` `keeper`; after a reload the engine adopts it the same way as the holder, and stops it (pid and argv verified) when it removes the claim. Every 10 s it runs `/usr/bin/touch -c <claim>` (never creates the file) only while the claim exists, `kill -0 <Herdr pid>` succeeds and the `engine` file is at most 520 s old; when the claim is missing or either check fails it exits without touching. The engine then touches `engine` (not the claim) on every tick. Result: Herdr death → claim stale within 45 s → restored within 60 s; a hang → `engine` older than 520 s → claim stale 45 s later → restored within 600 s; the watchdog's `last-restore` reason is `stale-claim` in both cases.
